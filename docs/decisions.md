## 2026-09-26 画像は、パスだけを貼り付けとして送り、読めない形式は JPEG にする

- Claude Code は画像のパスだけの貼り付けを添付として扱い、文章と混ざると添付にならない。そのため画像のパスを1枚ずつ貼り付けてから文章と Enter を送る
- HEIC と JPG を一緒に送ると HEIC がパスの文字のまま残って画像が欠けていたので、読めない形式は ffmpeg で JPEG に変換し、失敗した画像があれば送らない
- パスを入力欄に入れるのをやめ、サムネイルの添付欄にした
- 根拠: 7dd3dea、97f2966

## 2026-09-27 Cookie は SameSite=Lax にする

- Strict だと、チャットなど他のアプリから開いたリンクや、証明書の警告から進んだ直後に Cookie が送られず、ログインを求められていた（Pixel の Chrome で確認）

- 根拠: 9d3acc9

## 2026-09-27 LAN の証明書・待ち受けの範囲・Cookie の中身を変える（仮決定）

- 証明書を作り直すとき前のアドレスも引き継ぐ。家と職場を行き来するたびに警告を越える必要があったため（8c5f451）
- `-lan :7682` はすべてのネットワークで待ち受け、IPv6 のグローバルアドレスなど LAN 以外にも開いていた。プライベート・リンクローカル・Tailscale の IPv4 アドレスごとに待ち受けるよう変えた（e08d509、a1f7bce）。1つ失敗しても全体は止めない（de8430f）

## 2026-10-14 ログアウトと端末ごとの取り消し

SPEC.md の「予定」にあったもの。本人が寝ている間に作ったので、作り方は仮決定（本人の確認待ち）。

- Cookie の値を、トークンから計算した1つの値から、ログインごとのランダムな値に変えた。サーバーは値の SHA-256 だけを `devices.json` に持つ。値が1つだと、1台だけ締め出すことができないため
- 記録はトークンと同じ `~/.config/palmterm/` に置き、トークンから計算した値を一緒に書く。トークンが変わっていたら記録を全部捨てる。今までの「トークンを変えれば全端末を締め出せる」を保つため
- 前の形の Cookie（トークンから計算した値）は通さない。通すと、漏れた前の Cookie はトークンを変えるまで取り消せないまま残るため。代わりに、前から使っていた端末は一度ログインし直す（`palmterm url` の QR で開き直す）
- 最後に使った時刻は、リクエストのたびではなく1時間に1回までしかファイルに書かない
- 取り消したら、その端末の開いている WebSocket をすぐ切る（1008）。画面は 1008 で切られたとき、またはつなぎ直しが 401 で断られたときは、つなぎ直しを続けずに読み込み直し、ログインし直す案内を出す
- 一覧は、新しいボタンを増やさず、tmux ボタンのパネルの「その他」の行に置いた。たまにしか使わないため
- PC からの操作用のコマンド（`palmterm devices` など）は作っていない。なくしたスマホは、PC のブラウザで `palmterm url` の URL を開いて取り消せるため

## 2026-10-14 ログイン中の端末に名前を付ける

## 2026-10-15 `palmterm -version` で版を出す

- いま動いている palmterm がどの版かをコマンドで確かめるため（課題 0001）
- 版は `-ldflags "-X main.version=..."` で埋め込み、`make` では `git describe --tags --always --dirty` を使う。タグがまだ無いので、今は commit のハッシュ（変更があれば `-dirty` 付き）が入る
- `make` は Go と画面のファイルが変わったときだけ作り直すので、commit しただけ（ファイルは同じ）では実行ファイルの版は前のままになる。作り直すには `make -B`

## 2026-10-15 -help の説明を設定の言語で出す

- `-help` は `flag.Parse` の途中で出るので、`-config` の値はまだ使えない。`flag.Usage` の中で引数を自分で見て `-config` を探し、設定ファイルを読んで言語を決める
- 日本語の説明は flag の定義（英語）とは別の表（help.go の `flagUsageJa`）に持つ。英語は flag の既定の出力をそのまま使い、今と変えない。日本語は同じ形で自前で出し、`(default …)` も `（既定: …）` にした
- 設定ファイルが読めないときは、ログを出さずに英語で出す（-help のたびに警告を出さないため）

## 2026-10-15 画面にサーバーの版を出す

- スマホの画面から、つないでいるサーバーの版を確かめるため（課題 0004）
- 版は `/api/config` の応答に `version` として足した。画面に Vite でビルド時に焼き込む案は、画面だけ作り直したとき（`npm run dev` など）サーバーの版とずれうるのでやめた（本人も了承）

## 2026-10-15 commit の後の `make` で版を新しくする

- 0001 のレビューの指摘（課題 0005）。commit しただけではファイルが変わらないので、`make` が作り直さず版が古いまま残っていた。2026-10-15 の「作り直すには `make -B`」はやめた
- `make` のたびに `git describe` の値を `.version`（git では無視）と比べ、違うときだけ書き換える。palmterm はこれに依存するので、版が変わったときだけ作り直す。値が同じなら書かないので、何も変わっていなければ作り直さない
- `.version` を作るルールに FORCE を付ける書き方は、GNU make が作り直した扱いにするかが分かりにくいのでやめ、Makefile を読む時点で `$(shell …)` で書き換える形にした

## 2026-10-16 タグ名に ' などが入っても版を正しく埋め込む

- 0005 の Codex のレビューでは「タグ名に `'` が入ると毎回作り直す」という指摘だったが、テストで確かめると実際は逆で、`.version` を書き換える部分がシェルの文法の誤りで止まり、版が変わっても作り直さず古い版のまま残った

## 2026-10-16 送信ボタンを、送るものがあるときだけ出す

- 課題 0006。空のときの送信ボタンは Enter を送るだけで、その分テキストボックスが狭くなっていたため
- 出し分けは「文字が空でない」か「添付が1枚以上」。添付だけでも送信で画像のパスを貼るので、出す
- 隠すのは `hidden` 属性で、`#inputbar button` の `display: grid` に負けないよう `#inputbar button[hidden] { display: none }` を足した。flex の gap も消えるので、テキストボックスはボタンの幅と間の 4px だけ伸びる
- 空のときの Enter だけを送る手段は、Ctrl+Enter とキーバーの Ctrl → Enter で残す

## 2026-10-16 キーバーを隠せるようにする

- 課題 0007。物理キーボードをつないだときなど、キーバーが要らない間は端末を広く使うため
- 切り替えは tmux ボタンのパネルに「キーバー」の行を足して置いた。新しいボタンは増やさない
- tmux ボタンはキーバーと同じ段にあるので、段を残すと端末が広がらない。隠すときは段ごと消し、tmux ボタンをタブバーの右端（＋の右、同じ幅）に移した
- 覚える場所は文字サイズと同じく、このブラウザの localStorage（`palmterm.keybar`）。端末ごとに画面の広さや物理キーボードの有無が違うので、サーバーには持たない

## 2026-10-16 `palmterm logout-all` で全端末を締め出す

- 課題 0008。トークンを変えて再起動しなくても、コマンド1つで全端末を締め出すため（なくした端末が一覧のどれか分からないときなど）
- サーバーとは、palmterm-open と同じく実行時のフォルダの Unix ソケットでやり取りする。ただし `open.sock` は `-relay-browser=false` のとき作らないので、別に `control.sock` を常に置いた。HTTP の API にしなかったのは、ログインしていない PC のシェルからも打てて、かつ本人のユーザーだけに限れるため
- 実行時のフォルダは、今までは `MkdirAll(0700)` だけで、前から緩い権限で在れば直らなかった。起動時に 0700 にそろえ、ほかのユーザーのフォルダ（`/tmp/palmterm-<uid>` を先に作られた場合など）なら使わないようにした

- コマンドの出力は `palmterm url` に合わせて英語だけにした（設定ファイルを読まない）

## 2026-10-16 設定ファイルに版を持たせる

- 課題 0010。設定フォルダを別の PC へ写したときに、palmterm の新旧が混ざっても読めるようにするため
- 書いていなければ 1。今の書き方の版は `config.go` の `configVersion`（1）
- 新しい版のときは、知らない項目を書き間違いとして扱わない（新しい版では正しいかもしれないため）。`language` と `keys` を1つずつ `toml.Primitive` で読み、読めた方だけ使う。`language` が知らない値でも既定（英語）にするだけで、書き間違いとは知らせない

## 2026-10-16 テーマを設定ファイルの [theme] で変えられるようにする

- 課題 0011。組み込みのテーマは `default`（今までの色）、`light`（GitHub の明るい色に近いもの）、`solarized-dark`、`solarized-light` の4つ。中身は画面側の `web/src/theme.ts` に持つ（ボタンの色まで決めるので、端末の16色だけでなく帯・ボタン・パネル・入力欄・知らせの色もテーマごとに書いた）
- 16色は `black`〜`bright_white` の名前で1つずつ書く形にした。配列（`colors = [...]`）だと一部だけ上書きしにくく、何番がどの色か読みにくいため
- `background` は端末だけでなく画面の背景（`--bg`）も変える。default では両方同じ色で、分けると端末の外側だけ色が浮くため
- `accent` を書いたときは、薄い強調の色（`--accent-dim`、tmux ボタンの地など）を、その色を 25% で帯の色に混ぜて作る。組み込みのテーマでは手で決めた色を使う
- 色と名前の確かめは画面側で行う（キーバーの `[[keys]]` と同じ）。Go 側で確かめると設定全体の書き間違いになり既定に戻ってしまうが、完了の条件は「その色だけ既定に戻す」なので。`[theme]` の中の知らない項目名は、ほかの項目と同じく Go 側で書き間違いとして知らせる（設定全体が既定になる）
- 知らないテーマの名前は default にし、書いた色はその上に重ねる
- 端末の色は wterm の `.wterm` に CSS 変数で書いてあるので、端末の要素のインライン style で上書きする。ボタンの色は style.css の `:root` の変数（固定で書いていた色も変数にした）を `document.documentElement` で上書きする
- 新しい版の設定ファイルでも `[theme]` は読む（形が変わって読めなければ飛ばす）

## 2026-10-16 フォントを設定ファイルの [font] で変える（課題 0012）

- PC のフォントを名前で探すのは、まず palmterm が自分でフォントの置き場所（XDG・macOS の既定）を歩き、ファイルの name テーブルを読んで探す。fontconfig（`fc-list`）はそこに無いときだけ訊く。fc-list だけに頼ると macOS で使えず、テストも PC に入っているフォントに左右されるため。新しいライブラリ（golang.org/x/image など）は足さず、name テーブルを読む所だけを書いた
- 配るのは `/api/font` の1つの URL だけで、どのファイルを配るかはサーバーが設定から決める（URL にパスを載せない）。指定したフォント以外の PC のファイルを配らないため
- `file` の相対パスは、設定ファイルのあるフォルダから数える（既定の置き場所なら `~/.config/palmterm/`）。`-config` で別の場所を指したときも、設定ファイルと一緒に写せば移るように
- 端末の font-family は「Nerd Symbols、配ったフォント、family の名前、JetBrains Mono、…」の順にした。Nerd Symbols は unicode-range で私用領域だけを受け持つので、先頭に置けば選んだフォントがアイコンを持っていても今までどおりの形で描く
- 配るのは普通の太さの1ファイルだけにした（太字は合成）。太字のファイルも探して配るのは、使ってみて要るとなったら足す
- .ttc（フォントの集まり）は、ほかに無いときだけ選ぶ。ブラウザによって読めないことがあるため

## 2026-10-16 画面からフォントファイルを足す（課題 0013）

- 保存先は設定ファイルのあるフォルダの `fonts/`。`[font]` の `file` の相対パスと同じ所から数えるので、知らせた `file = "fonts/名前"` をそのまま書けば使える
- フォントの画面は index.html に置かず、`web/src/fontfiles.ts` で作って body に足した（課題の scope が web/src だったため）。見た目はログイン中の端末の画面にそろえた
- 入口は tmux パネルの「文字」の行（文字サイズの横）にした。「その他」の行はボタンが3つあり、スマホの幅では詰まるため
- 受け付けるのは 1 回に 1 ファイル。拡張子と中身の先頭の両方で確かめる。.ttc は `[font]` の `file` では使えるが、ブラウザで読めないことがあるので画面からは受け付けない
- 大きさの上限は 32 MB（日本語のフォントの .otf でも収まる大きさ）
- 名前は画像のアップロードと同じ `safeFileName`（英数字と `. _ -` だけ）で直す。英数字の無い名前（日本語だけなど）は `file.ttf` のようになるが、設定ファイルに書きやすく、端末で打ちやすいことを優先した。上書きはせず番号を付ける（消した・入れ替えたつもりでないものを壊さないため）
- 削除は `fonts/` の直下のフォントの拡張子のファイルだけ（シンボリックリンクやフォルダは消さない）

## 2026-10-16 画面でテーマとフォントを選び、設定ファイルに書き戻す（課題 0014）

- 書き戻しは TOML を読んで書き直すのではなく、文章のまま `[theme]` の `name` と `[font]` の `file` の行だけを書き換える。BurntSushi/toml で読んで書き出すと、コメント・並び順・書き方が消えるため。コメントを残せる TOML のライブラリも足さなかった（依存を増やさず、書き換えるのは1行の文字列だけなので）
- 文章のままの書き換えは、インラインのテーブルやドットの付いた書き方、複数行の文字列などで行を見つけそこなうことがある。そこで、書き換える前と後をそれぞれ `map[string]any` に読み、「前の中身に今回の変更だけを当てたもの」と「書き換えたあとの中身」が同じであることを確かめ、違えば書かずに手で直すよう知らせる。新しい版の設定ファイル（知らない項目がある）でもこの確かめ方なら壊さない
- 書き間違いがあって読めない設定ファイル（configStore.get がエラーを返すもの。知らない項目を含む）は書き換えない。読めていない所を palmterm が上書きすると、本人の意図と違う形で「直って」しまうため
- 保存は同じフォルダの一時ファイルに書いてから置き換える（途中で止まっても壊れたファイルを残さない）。dotfiles をリンクで管理していることがあるので、リンクの先を書き換え、元の権限を引き継ぐ
- テーマの名前の一覧は Go 側（`themeNames`）にも持ち、画面の `THEMES` と同じことを `TestThemeNamesMatchTheScreen` で確かめる。サーバーで知らない名前を断るため
- テーマは tmux パネルに「テーマ」の行を足してボタンで選ぶ（select ではなく、ほかの行と同じボタン）。フォントはパネルの「フォント」から開く一覧の各行に「使う」を足した。パネルの行にフォントの名前を並べると、足したフォントが増えたときに収まらないため
- フォントを「既定」に戻すときは `[font]` の `file` の行を消す（`family` は残す）。選ぶときも `family` は消さない（`file` が優先されるので、消さなくても選んだものになる）
- 選び直したときは、前に配ったフォント（`palmterm font` の FontFace）を外してから足す。同じ名前の FontFace が2つあるとブラウザがどちらを使うか決まらないため。文字の大きさは wterm が測り直す（ResizeObserver で見ている W の幅が変わる）
- テーマ・フォントは端末ごとには覚えず、設定ファイルだけに書く。別の端末で読み込み直しても同じになるようにするため（文字の大きさやキーバーの出し入れは端末ごと）

## 2026-10-16 大きい画面では板を中央に浮かせる（課題 0016）
